# 화면 설계: 목록, 품목 상세, 시세 (+ 매대 앞 바로 확인)

- 날짜: 2026-10-16
- 상태: 승인(2026-10-16). [제안] 항목도 사용자가 그대로 승인했다.
- 근거 문서: `docs/product.md`, `docs/data-sources.md`(2026-10-16 조사), `docs/tracking/decisions/index.md`(D-003~D-006), 가계부 `DESIGN.md`(jootaewan-hub/account-book)
- 시안: `.superpowers/brainstorm/`의 `detail-layout.html`, `list-layout.html`, `market-layout.html`(로컬 전용, 커밋 안 함). 시안의 숫자는 모두 예시다.

표기: **[사용자]**는 사용자가 정한 것, **[제안]**은 Claude가 정했고 사용자가 아직 따로 확인하지 않은 것, **[빌더]**는 만드는 사람이 정해도 되는 것.

## 1. 왜 만드는가

두 사람이 장을 볼 때, 특히 **마트 매대 앞에서 상품 하나를 들고** 다음을 한 번에 알고 싶다 [사용자]:

1. 이 상품에 문제가 없는지(회수·판매중지·부적합 등)
2. 여러 쇼핑몰·마트에서 얼마인지(쿠팡, 컬리, 네이버, 오늘의집, GS, 이마트, 홈플러스, 킴스클럽 등)
3. 평가가 좋은지(평점·후기)
4. 성분이 어떤지
5. 더 좋은 상품이 있는지

사용자는 "최대한 많은 출처에서" 가격을 모으기를 원한다. 동시에 프로젝트 규칙상 화면의 숫자는 출처가 있는 값만 쓴다(CLAUDE.md). 이 둘을 함께 지키는 것이 이 설계의 핵심이다.

## 2. 목표·비목표·실패 조건

**목표**
- 품목 상세 첫 화면(요약 네 칸)만 보고 살지 말지 판단할 수 있다.
- 가격은 출처가 허용하는 한 많이 모으고, 자동으로 못 가져오는 곳은 바로가기와 직접 기록으로 메운다.
- 목록은 장 보기 전(어디서 살지)과 마트 안(매대 순서) 모두에 쓸 수 있다.
- 시세는 지켜보는 품목의 변화와 이번 주에 싸진 품목을 함께 보여 준다.

**비목표 (이번 설계에서 다루지 않음)**
- 담기 화면의 세부, 기록(지출) 화면, 설정 화면. 이 문서는 이들로 들어가는 입구만 정한다.
- 후기 본문 요약, 상품 추천 문장 생성.
- 쿠팡·SSG·G마켓 등 수집을 거부하는 곳의 자동 수집.

**실패 조건 (동작해도 실패로 본다)**
- 출처·기준 시각 없는 가격·시세·등락률이 하나라도 화면에 나온다.
- 기록이 없을 때 "안전함", "문제 없음"이라고 쓴다.
- 오래된 가격(검색 결과 발췌, 캐시 만료분)을 지금 가격처럼 보여 준다.
- 앱이 AI처럼 보인다(채팅창, 반짝이 아이콘, "분석 중…", 모델이 쓴 판단 문장).
- 회수 대상 품목이 목록에 있는데 경고가 안 뜬다.

## 3. 제약

- 디자인은 가계부 `DESIGN.md` 체계를 따른다(D-005): 흰 바탕 + 귀리색 묶음 면, 먹색 주 버튼, SUIT 글꼴, 고정폭 숫자, 화면당 큰 숫자 하나, 그림자 없음, 한국어 문장형 제목, 점으로 이은 정보 문자열 금지. 장보기 확장분(경고 배지, 출처 태그, 시세 등락 색, 상품 이미지 타일, 다크 모드)은 장보기 `DESIGN.md`에 새로 쓴다.
- 시세 등락 색: 오르면 `clay`(흙빛) ▲, 내리면 `indigo`(쪽빛) ▼ [제안, 국내 관례인 빨강/파랑을 가계부 색으로 옮김]. 색만으로 알리지 않고 ▲▼와 숫자를 함께 쓴다.
- 마트에서 한 손으로 쓴다: 터치 대상 44px 이상, 주요 동작은 화면 아래.
- 390px 휴대폰과 1280px 화면, 라이트·다크 모두 Playwright로 캡처해 확인한 뒤에 끝났다고 한다.
- 수집 원칙: robots.txt가 막는 경로, 약관이 자동 수집을 금지하는 곳은 받지 않는다. 허용된 곳도 품목별 하루 한 번만 받고 캐시한다.
- 네이버 검색 API 결과는 AI에 넣지 않고 서버 캐시는 21일을 넘기지 않는다(2026-09-07 약관).

## 4. 가격 출처와 표시 규칙

가격 한 줄 = (어디 가격인지) + (값) + **출처 태그** + **확인 시각** (+ 배송비가 있으면 배송비).

| 출처 태그 | 무엇 | 비고 |
|---|---|---|
| 다나와 | 다나와 상품 페이지 본문의 쇼핑몰별 최저가(약 10줄)와 최저가·판매처 수 | 1순위. 11번가·G마켓·옥션·롯데ON·이마트몰·신세계몰 등의 값이 이 경로로 온다. `/info/ajax/`는 쓰지 않는다. |
| 에누리 | 최저가·최고가·판매처 수 | 다나와 보조 |
| 상품 페이지 | 컬리, CJ더마켓, 홈플러스 상품 페이지의 JSON-LD 가격 | 값이 0이면 버린다 |
| 로우차트 | 쿠팡 상품의 현재가와 관측 최저·평균·최고가 | 쿠팡 자동 가격의 유일한 경로 |
| 참가격 | 매장 가격(이마트, 농협하나로, 롯데슈퍼, GS더프레시, 편의점) | 격주 조사일을 기준일로 표시 |
| KAMIS | 신선식품 소매 평균 | 시세 화면과 신선 품목 |
| 우리가 산 값 | 가계부에 저장된 우리 구매 기록(날짜, 사람, 플랫폼, 개당·단위 가격) | D-003으로 같은 DB에서 읽는다. 태그 색을 달리한다(`blush-soft` 바탕, `rose-ink` 글자) [제안] |
| 캡처 | 사용자가 올린 쇼핑몰 화면 캡처나 가격표 사진에서 읽은 값 | 캡처 시각과 사람을 함께 저장. 읽은 값은 저장 전에 사용자가 확인한다 |

- 검색(Exa 등)은 **상품 페이지 주소를 찾는 데만** 쓴다. 검색 결과 발췌에 든 가격은 화면에 내지 않는다.
- 자동으로 못 가져오는 곳(쿠팡, 이마트몰, 킴스클럽몰, 오늘의집, 롯데ON, G마켓 등)은 **바로가기 버튼**으로 둔다 [사용자]. 버튼은 그 쇼핑몰의 검색 결과 화면을 상품명으로 연다.
- 바로가기 옆에 "화면 캡처로 가격 넣기"를 둔다 [사용자].
- "지금 찾은 가장 싼 값"은 확인 시각이 **오늘**인 값 중에서 고른다. 참가격·로우차트 관측 최저·우리가 산 값처럼 과거 값은 비교 줄에는 나오지만 "가장 싼 값"으로 뽑지 않는다 [제안].
- 같은 상품인지 맞추는 기준(용량·개수·바코드)이 다른 줄은 "다른 용량"으로 구분하고 100g(또는 1개)당 가격을 함께 쓴다.

## 5. 화면 ① 품목 상세 — 요약 네 칸 + 탭 [사용자: B안]

**머리**: 상품 사진(있으면), 상품명, 업체명, 분류.

**요약 네 칸** (2×2, 귀리 면):
| 칸 | 내용 | 값이 없을 때 |
|---|---|---|
| 가장 싼 값 | 오늘 확인한 최저가와 곳(아래 줄) | "확인 못 함" |
| 식약처 기록 | 기록이 있으면 흙빛 배지 + "회수 1건"처럼 / 없으면 "찾은 기록 없음" | 대조 실패 시 "확인 못 함" |
| 평점 | 평점 숫자와 출처 | "확인 못 함" |
| 더 나은 상품 | 개수 | "없음" 또는 "확인 못 함" |

식약처 기록이 있으면 요약 네 칸 위에 경고 줄을 따로 둔다: 사유, 등급, 등록일, 출처(식약처 I0490 등) [제안].

**탭**: 가격 | 안전 | 평가 | 성분 | 대안. 처음 열면 가격 탭.

- **가격 탭**: 4절 규칙의 줄 목록(가장 싼 값부터), 그 아래 바로가기 버튼들과 "화면 캡처로 가격 넣기". 품목이 다른 용량으로 섞이면 단위가격을 함께 쓴다.
- **안전 탭**: 확인한 출처 목록과 결과. 출처: I0490 회수·판매중지, I2620 검사부적합(국내), I2715 해외직구 위해식품. 각 출처마다 "확인 범위(언제까지 등록분)"와 결과. 기록이 없으면 "확인한 범위에서 찾은 기록 없음". 제조사 행정처분(I0470, 업소 단위)은 인허가번호로 이어질 때만 "제조사 행정처분 기록"으로 따로 보여 준다(연결 정확도 확인 필요). 제품 변경: 참가격 "용량 변경" 게시글에 이 상품이 있으면 표시, 원재료 보고 변경일(C002 CHNG_DT)이 최근이면 "원재료 보고 변경 있음(날짜)" — 무엇이 바뀌었는지는 이전 값과 비교된 경우에만 쓴다.
- **평가 탭**: 평점과 후기 수, 출처, 기준일, "원래 페이지에서 후기 보기" 링크. 후기 본문을 복제하거나 요약하지 않는다 [사용자 동의, 저작권].
- **성분 탭**: 식약처 영양성분DB 값(열량, 나트륨, 당류, 지방, 포화지방, 단백질 등, 기준량 명시)과 원재료(C002, "식품유형명이 섞여 포장지 표시와 다를 수 있음" 안내). 값이 없으면 "확인 못 함".
- **대안 탭**: 대안 상품마다 이유 태그를 붙인다 [사용자 기준]:
  - **평가가 좋음**: 평점이 더 높거나 후기가 더 많음(다나와).
  - **브랜드 평가가 좋음**: 그 브랜드의 같은 종류 상품 평점 평균을 몇 개로 계산했는지와 함께("이 브랜드 만두 8개 평균 4.7, 다나와") + 최근 1년 식약처 회수·부적합 건수 [사용자: 브랜드는 리뷰·평가로 판단 / 회수 건수 병기는 제안].
  - **성분 수치가 나음**: 같은 종류 안에서 나트륨·당류 등의 차이를 숫자로만("100g당 나트륨 30% 적음"). "건강하다" 같은 판정 문장은 쓰지 않는다.
  - **더 쌈**: 100g(또는 1개)당 가격 차이.
  - 회수·부적합 기록이 있는 상품은 대안에서 뺀다.
  - 대안 후보를 고르는 방법(같은 종류 판단)은 [빌더]가 정하되, 모델이 지어낸 상품·숫자가 섞이지 않게 모든 후보와 수치는 4절 출처에서 온 것이어야 한다.

**진행 표시**: 탭·칸마다 하는 일을 그대로 적는다("다나와 가격 확인 중", "식약처 목록 확인 중"). 실제 단계가 바뀔 때만 문장을 바꾸고 지어낸 진행률은 쓰지 않는다.

## 6. 화면 ② 장보기 목록 — 두 가지 보기 [사용자: A·B 둘 다]

**상단**: 화면 제목, 요약 세 칸(살 것 개수, 찾은 최저가 합계, 확인 못 함 개수), 보기 전환 "분류별 | 어디서 살지". 마지막으로 고른 보기는 사람마다 기억한다 [제안].

**먼저 볼 것**: 식약처 기록이 있는 품목은 두 보기 모두에서 맨 위에 고정한다 [제안].

- **분류별 보기**: 정육·수산·채소·과일·유제품·계란·가공·냉동·음료·생활용품 순서(매장 동선)로 묶는다.
- **어디서 살지 보기**: "온라인이 더 싼 것"과 "마트에서 살 것"으로 나눈다. 온라인이 더 싸다는 판단은 오늘 확인한 온라인 최저가(배송비 포함)와 매장 기준 가격(참가격 또는 우리가 산 매장 값)을 비교해 둘 다 있을 때만 내린다. 비교할 값이 없으면 "마트에서 살 것"에 두고 "비교 못 함"을 적는다 [제안].

**행**: 체크 원(한 번 누르면 산 것), 상품명·용량·개수, 둘째 줄(누가 담았는지 색 점 + 이름, 시세 등락 또는 평점 또는 경고), 오른쪽 최저가와 곳. 가격을 못 찾았으면 "가격 확인 못 함" 태그. 산 품목은 취소선과 "누가 샀어요, 금액". 행을 누르면 품목 상세.

**아래**: "담기" 주 버튼, 그리고 "바코드로 상품 보기" 입구(7절).

두 사람이 같은 목록을 실시간으로 본다(Supabase Realtime).

## 7. 매대 앞 바로 확인 [사용자: 반드시 있어야 함]

목록에 담지 않고 상품을 바로 확인하는 길.

- 입구: 목록 화면 아래의 "바코드로 상품 보기"와 담기 화면 [제안, 위치는 빌더가 조정 가능].
- 바코드를 찍으면: (1) 식약처 회수·부적합 목록의 바코드와 바로 대조, (2) 바코드로 상품명을 찾는다 — 상품 페이지 JSON-LD의 `gtin13`, 검색, 실패하면 포장 사진을 찍어 제품명 읽기로 넘어간다. 공공 바코드 DB(C005 등)는 2018년 이후 갱신이 멈춰 쓰지 않는다.
- 포장 사진을 찍으면 제품명·용량을 읽어 확인 화면을 거친 뒤 품목 상세를 연다.
- 품목 상세 하단에 "목록에 담기" 버튼.
- 바코드→상품명 성공률은 확인 필요다. 실패해도 회수 대조 결과는 먼저 보여 준다.

## 8. 화면 ③ 시세 — 한 화면에 셋 [사용자: A·B 둘 다]

위에서부터:
1. **지켜보는 품목**: 품목마다 현재 소매가, 30일 추이 선(등락 방향 색), 1주 전·평년 대비. 30일 추이는 우리가 매일 쌓은 KAMIS 값(`price_points`)으로 그리며, 쌓인 날이 30일 미만이면 쌓인 만큼만 그리고 "10월 2일부터 기록"처럼 적는다.
2. **이번 주 움직임**: KAMIS 품목 중 많이 내린 것("지금 사기 좋은")과 많이 오른 것. 기간 전환: 1주 전 | 1개월 전 | 평년. 각 행에 이전 값 → 지금 값. 품목 수는 [빌더]가 정한다(예: 각 5개).
3. **식약처 최근 회수·판매중지**: 등급 배지, 제품명, 업체, 사유, 등록일. "어디까지 등록분" 기준일을 묶음 제목에 쓴다.

화면 맨 위에 "KAMIS 소매가격, 갱신 시각"을 적는다. 행을 누르면 그 품목의 신선 품목 상세(8-3절)로 간다. 지켜보기 추가·해제는 품목 상세나 행에서 한다 [빌더].

## 7-1. 어떤 상품인지 정하기 [사용자]

- 품목을 담으면 후보 상품을 보여 주고 **사용자가 직접 하나를 고른다.**
- 같은 제품이라도 무게·수량이 다르면 다른 상품이다(예: 비비고 왕교자 1.05kg과 1.4kg, 우유 900ml와 2.3L). 후보 목록에서 용량·개수를 크게 쓰고 100g(또는 1개)당 가격을 함께 보여 준다.
- 고른 상품은 가구 단위로 기억해, 같은 이름과 용량을 다시 담으면 바로 그 상품으로 잡는다. 바꾸기는 품목 상세에서 [제안].
- 고르기 전 품목은 "상품 고르기 전" 상태로 목록에 남고, 가격·평점 칸은 비운다. 식약처 대조는 이름·업체로 먼저 해 본다(8-2절의 "비슷한 기록" 규칙).
- 신선 품목(삼겹살, 대파 등)은 상품을 고르지 않고 KAMIS 품목으로 연결한다(8-3절) [제안].

## 7-2. 지역과 매장 [사용자: 온라인·오프라인 둘 다, 경기도 성남시 분당구]

- 설정에 "사는 곳"(기본 성남시 분당구)과 "자주 가는 매장"을 둔다. 매장 가격은 참가격에서 분당구 근처 조사 판매점을 고른다 [제안]. 참가격에 없는 홈플러스·롯데마트·킴스클럽 매장 가격은 "우리가 산 값"과 가격표 사진으로만 채운다.
- KAMIS 시세는 성남 지역 값이 있으면 그 값을, 없으면 가까운 조사 지역(예: 수원) 또는 전국 평균을 쓰고 화면에 어느 지역 값인지 적는다. 성남 지역 코드 존재 여부는 확인 필요.
- "어디서 살지" 보기의 매장 기준 가격은 자주 가는 매장의 참가격 → 우리가 산 매장 값 순서로 고른다.

## 8-1. 확인이 언제 도는가 [제안]

- 품목을 담고 상품을 고르는 순간 품목 확인(가격·식약처·평점)을 자동으로 시작한다. 목록 줄의 최저가·합계와 회수 품목 고정이 이 값에 기대기 때문이다.
- 아직 사지 않은 품목은 하루 한 번 서버 정기 작업으로 다시 확인한다. 같은 상품·같은 날은 캐시를 돌려준다. 두 사람이 쓰므로 하루 호출 수는 품목 수 × 출처 수 수준이다.
- 식약처 목록은 매일 받아 두므로, 새 회수가 등록되면 목록에 있는 품목과 즉시 다시 대조한다.
- 품목 상세를 열 때 그날 확인한 값이 없으면 그때 확인한다.

## 8-2. 식약처 대조의 네 가지 상태 [제안]

| 상태 | 언제 | 화면 |
|---|---|---|
| 기록 있음 | 바코드 또는 품목보고번호가 일치 | 흙빛 배지, 먼저 볼 것에 고정 |
| 비슷한 기록 있음 | 바코드가 없고 제품명·업체명이 비슷함 | 옅은 흙빛 배지 "비슷한 제품 기록", 먼저 볼 것에 고정, 기록의 제품명·업체·포장 단위를 나란히 보여 주고 "같은 제품인지 포장을 확인해 보세요" |
| 찾은 기록 없음 | 대조했으나 일치·유사 없음 | "확인한 범위에서 찾은 기록 없음" + 확인한 출처와 범위 |
| 확인 못 함 | 대조할 정보가 부족하거나 출처 오류 | "확인 못 함" |

놓치는 쪽이 잘못 붙는 쪽보다 위험하므로, 애매하면 "비슷한 기록 있음"으로 올린다. 유사도 기준은 [빌더].

## 8-3. 신선 품목(정육·수산·채소·과일)의 상세 [제안]

- 요약 네 칸: 오늘 시세(KAMIS 소매), 1주 전 대비, 평년 대비, 식약처 기록(수산물·가공육 등 해당할 때).
- 탭: 시세 | 가격 | 안전. 시세 탭은 KAMIS의 오늘·1일·1주·2주·1개월·1년·평년 값과 우리가 쌓은 추이 그래프, 우리가 산 값. 평가·성분·대안 탭은 두지 않는다.
- 목록 품목과 KAMIS 품목 연결(예: "삼겹살 600g" → KAMIS 삼겹살 100g)은 분류 사전으로 하고, 연결되지 않으면 시세 칸은 "확인 못 함" [빌더].

## 9. 상태 문구

모든 화면에 빈 상태·불러오는 중·오류를 따로 둔다. 예:
- 목록 비었음: "아직 담은 게 없어요. 아래 담기나 바코드로 시작해 보세요."
- 가격 못 찾음: "가격 확인 못 함" + 바로가기.
- 출처 오류: "다나와 가격을 지금 불러오지 못했어요. 10월 16일 09:10에 확인한 값을 보여 드려요." — 캐시 값을 보여 줄 때는 반드시 그 시각을 쓴다.

## 10. 만드는 사람에게 맡기는 것 [빌더]

- 컴포넌트 구조, 상태 관리, 캐시 테이블 설계, 수집 함수 나누기.
- 대안 후보 선정 알고리즘(출처 값만 쓴다는 조건 안에서).
- 아래 탭 구성과 담기·기록·설정으로 가는 길(이번 설계 범위 밖, 가계부 탭 규칙을 따름).
- 다크 모드 색 값(가계부에 없음, 장보기 `DESIGN.md`에 대비 검증과 함께 정의).
- 1280px 넓은 화면 배치(가계부의 넓은 화면 규칙을 따름).

## 10-1. 출처가 막혔을 때와 만드는 순서 [제안]

- 다나와 등 주요 출처의 확인(약관, Edge Functions에서의 접근)을 계획 맨 앞에 둔다. 막히면 그 출처를 빼고 나머지 출처·바로가기·캡처로 간다. 국내 서버나 집 PC 같은 별도 실행 환경은 쓰지 않는다. 필요해지면 그때 따로 결정한다.
- 브랜드 평가는 이미 받아 둔 상품들의 평점으로만 계산하고, 상품 수가 적으면(예: 3개 미만) 브랜드 평가 이유 태그를 붙이지 않는다. 브랜드 평균을 위해 따로 대량 수집하지 않는다.
- 만드는 순서는 status.md를 따른다: 목록·품목 상세(가격·안전)·시세를 먼저, 화면 캡처 가격·포장 사진 읽기·바코드는 그 뒤. 사진 읽기는 status.md의 "Claude 호출 방식" 결정이 나야 시작한다.

## 11. 확인 필요 (코드 전에 실제 호출로 확인)

`docs/data-sources.md`의 "확인 필요" 중 이 설계가 기대는 것:
- 다나와·에누리·컬리·CJ더마켓·홈플러스 약관의 자동 수집 조항, 그리고 Supabase Edge Functions에서 요청해도 막히지 않는지.
- 다나와·에누리 식품 판매처 범위(쿠팡·컬리·홈플러스가 나오는지).
- 로우차트 약관과 쿠팡 상품 매칭 방법.
- 참가격 API 실제 응답(판매점별 가격, 조사일).
- 식품영양성분DB 응답 필드와 제품 매칭률.
- 바코드 → 상품명 성공률.
- KAMIS 소매가격의 성남 지역 코드 유무, 참가격의 분당구 근처 조사 판매점.
- 다나와 MCP를 서버에서 쓸 수 있는지(커넥트웨이브 문의).
