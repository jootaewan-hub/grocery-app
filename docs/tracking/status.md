## 열린 문제

- 담기 자동 나누기는 분류 사전에 있는 단어에 기댄다(2026-10-17). 사전에 없는 단어가 이어지면 한 품목으로 남는다(예: "닭 가슴살 계란" → 한 품목, "우유 요거트" → 한 품목). 미리보기에서 보이므로 쉼표로 나누면 된다. 실제로 자주 틀리는 단어가 보이면 사전(`src/lib/categories.ts`, `src/lib/parse.ts`의 MODIFIERS·FORM_SUFFIXES·COMPOUNDS)에 더한다.
- 기본 수량(`src/lib/staples.ts`)은 두 사람·일주일 저녁 4~5번 기준으로 정한 제안값이다. 실제 장보기와 다르면 표를 고친다.

- 네이버 쇼핑 검색 API 종료(2026-07-31)로 `docs/architecture.md` 데이터 흐름의 "네이버 쇼핑 검색"과 CLAUDE.md의 "네이버 검색 API는 하루 25,000회" 규칙이 맞지 않게 됐다. 가격 출처가 정해지면 함께 고친다.
- 비밀번호 재설정 메일 링크가 어디로 돌아오는지: 공유 프로젝트의 Site URL이 가계부 주소라서 장보기 앱에서 재설정을 요청해도 가계부로 돌아갈 것으로 보인다(추측, 로그인 화면 만들 때 확인).
- Realtime DELETE 이벤트가 `grocery.items`(RLS)에서 실제로 오는지 확인 필요. 목록 화면은 화면 복귀 때도 다시 읽으므로 늦게라도 맞춰진다.
- 가격이 붙는 계획 ④에서 0원·음수 가격은 출처 값이 아니므로 버린다(목록 계산은 이미 0 이하를 없는 값으로 취급).
- 빼기 되돌리기: 두 번째 품목을 빼면 첫 번째 품목의 되돌리기 알림이 사라진다(첫 번째는 그대로 빠짐).
- 식약처 예약 실행: 저장소에 60일 동안 활동이 없으면 GitHub가 예약 워크플로를 멈춘다. 멈추면 Actions에서 다시 켠다. 목록 화면은 마지막 성공이 48시간을 넘으면 확인 상태 줄로 알린다.
- 식약처 첫 동기화 소요 시간이 Edge Function 시간 한도 안인지 확인 필요(I2715 5,013건 = 6번 호출, 한 번 20초 제한). 첫 실제 동기화 때 본다.
- I2715 해외직구 차단 기록은 차단 종료일 전까지 계속 대조해서 "비슷한 기록"이 많이 뜰 수 있다(알림 피로). 실제 수집분 5,013건 중 5,004건이 아직 차단 중(종료일 대부분 먼 미래)이라 대상이 거의 전부다. 실제 목록에서 얼마나 뜨는지 확인한다.
- 확인 상태는 `sync_runs` 성공 기록 최근 30건에서 서비스별 마지막 성공을 찾는다. 한 서비스만 오래 실패하면 그 서비스가 30건 밖으로 밀려 "확인한 범위"에서 빠질 수 있다.
- 식약처 "기록 있음"(바코드 일치)은 상품·바코드가 붙는 계획 ⑥에서 한다. 지금은 모두 "비슷한 기록"(제품명·업체명 단어 일치)이다.
