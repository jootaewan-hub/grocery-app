## 1. 쇼핑 가격

### 1-1. 네이버 쇼핑 검색 API — 종료

- **2026-07-31에 종료됐다.** 유예 없음, 기존 키도 호출 불가, NAVER API HUB 포함 대체 API 없음. 공지 원문으로 확인: https://developers.naver.com/notice/article/32530 , https://developers.naver.com/notice/article/32564
- HUB의 Shopping Insight는 클릭 추이 비율만 주고 가격·판매처가 없다.
- 네이버 가격비교 페이지(search.shopping.naver.com)는 robots.txt가 모든 봇에 `Disallow: /`이고, 직접 요청하면 HTTP 418(접속 제한)이 돌아온다.

### 1-2. 상품 페이지 구조화 데이터(JSON-LD)

서버에서 상품 페이지 원본을 받아 schema.org `Product/Offer`의 `price`를 읽는 방식. 2026-10-16 curl로 확인.

| 곳 | robots.txt | 결과 |
|---|---|---|
| 컬리 | 전체 허용 | `offers.price` 있음(예: goods/1000466118 → 16600 KRW, goods/5082274 → 9640). 같은 날 검색 요약에는 9,630원으로 나와 값이 달랐다 → 직접 받은 값과 받은 시각만 쓴다. 후기 수(`reviewCount`) 있음, 평점 없음. |
| CJ더마켓 | 상품 페이지 허용 | `price` 11020과 `gtin13`(바코드) 있음 → 바코드로 같은 상품을 맞출 수 있다. |
| 다나와 | 상품 페이지 `/info/` 허용, 몰별 가격 AJAX `/info/ajax/`는 금지 | `AggregateOffer`(최저가 `lowPrice`, 판매처 수)와 `aggregateRating`(예: 4.8, 후기 97,974) 있음. 몰별 가격 목록은 금지 경로라 쓰지 않는다. 식품 목록(라면·생수 등)이 있다. 오픈 API는 2019-04-30 종료. |

| 오늘의집, 롯데ON, 킴스클럽몰, GS샵 | 별표 그룹 `Disallow: /` | 확인하지 않음(robots 존중). |
| GS fresh | — | 2023-11-30 서비스 종료. 지금은 우리동네GS·네이버 장보기에서 판매. |

- 원칙(제안): robots.txt가 막는 곳과 약관이 자동 수집을 금지하는 곳은 수집하지 않는다. 허용된 곳도 품목 확인 때 한 번씩만 받고 캐시한다.
- 참고 판례: 여기어때 크롤링 사건은 형사 무죄(대법원 2021도1533)였지만 민사에서는 부정경쟁방지법 위반으로 10억 원 배상(2018가합508729)이 인정됐다. 대량 수집은 하지 않는다.
- 확인 필요
  - 각 몰 이용약관의 자동 수집 조항(컬리·CJ더마켓·홈플러스·다나와). 다나와 약관은 인코딩이 깨져 읽지 못했다.
  - Supabase Edge Functions(해외 IP일 수 있음)에서 요청해도 막히지 않는지(추측: 막힐 수 있음).

### 1-2-1. 종합 가격비교·가격 추적 사이트 (2026-10-16 curl로 robots와 페이지 1~2건씩 확인)

| 곳 | robots | 약관 | 가격 데이터 | 판매처(표본) |
|---|---|---|---|---|
| 다나와 `/info/` | 허용(`/info/ajax/`·`/api/`·`/bridge/` 금지) | 제24조② "영리목적" 복제 금지(2026-07-13 시행). 자동 수집 조항은 찾지 못함 | JSON-LD AggregateOffer + **HTML 본문에 "쇼핑몰별 최저가" 약 10줄**(`data-base-price`, `data-delivery-price`, 몰 로고 alt=몰 이름) | 11번가, 옥션, G마켓, 롯데ON, 배민상회, 신세계몰, 이마트몰, 현대Hmall, W쇼핑 |
| 에누리 `price.enuri.com/catalog/` | 허용(`/api/*` 금지, Crawl-delay 1) | 제12조③ "영리목적" 복제·배포 금지 | JSON-LD AggregateOffer(최저·최고가, 판매처 수). 몰별 목록은 Next.js RSC 페이로드(구조가 바뀌면 깨지기 쉬움). 가격 갱신일 표시 | 11번가, G마켓, 옥션, SSG.COM, 이마트몰, 신세계몰, 롯데ON |
| 로우차트 상품 페이지 | 허용(`/api/`, `?keyword=` 금지) | 약관 페이지 못 찾음 | JSON-LD Product: 현재가, 관측 최저·최고·평균가, 최근 변동일. 이력 그래프는 그림뿐. FAQ에 "쇼핑몰 API로 수집" | 쿠팡만 |
| 다나와 MCP(2026-08-05 출시 보도) | — | 업체회원 약관에 가격정보를 "API, MCP 등"으로 활용한다는 문구 | 50여 개 몰 가격을 시간마다 갱신한다고 보도. 제3자 목록의 엔드포인트는 403 | — |

- **2026-10-19 다시 확인(집 PC에서 curl, 요청 3건)**:
  - 다나와 검색 `search.danawa.com/?query=…`(옛 `dsearch.php`는 이 주소로 307): robots 허용, **Crawl-delay 10**(10초에 한 번). 응답 HTML 한 장에 상품 40개가 서버에서 그려져 온다(`li[data-product-seq]` = pcode). 줄마다 상품명(용량 포함, 예: "CJ제일제당 비비고 왕교자 1.05kg"), 수량별 최저가(1개·2개 등), 100g당 가격이 있다. JSON-LD `ItemList`에는 앞 6개만(이름·주소·이미지, 가격 없음). 클래스 이름이 Tailwind라 구조가 바뀌면 깨지기 쉽다.
  - 다나와 상품 페이지 `prod.danawa.com/info/?pcode=`: JSON-LD `Product`에 `AggregateOffer`(lowPrice, offerCount)와 `AggregateRating`(예: 4.8, 후기 9,099). 본문 "쇼핑몰별 최저가"에 약 10줄: 가격·배송비(`data-base-price`, `data-delivery-price`)와 몰 로고 `alt`(롯데ON, G마켓, 옥션, 11번가, SSG.COM, 신세계몰, 이마트몰 등). 바코드(gtin)는 없다.
  - 주의: 상품 페이지는 기본 수량이 묶음(예: "1.05kg (3개)" lowPrice 27,650)일 수 있고, 검색 결과의 1개 가격(10,380)과 다르다. 수량을 맞춰 비교해야 한다.
  - **Supabase Edge Functions에서도 막히지 않는다**(2026-10-19 임시 함수 `danawa-probe`로 한 번씩 호출): 실행 리전 `ap-northeast-2`(서울), 검색 200·후보 40개·0.5초, 상품 페이지 200·AggregateOffer 있음, 차단 문구 없음. 시험 뒤 그 함수는 외부 호출 없이 410만 돌려주게 바꿨다(대시보드에서 지워도 된다).
- 쓰지 않는 곳: 폴센트·11번가(robots 전체 금지, 11번가 Open API 문서는 있으나 현행 여부 미확인), G마켓·옥션(약관 제36조 자동 접속 프로그램 금지, 403), 카카오 쇼핑하우(robots 금지), 위메프(2025-11-10 파산), 티몬(영업 안 함).
- 마트 전단: 이마트 전단은 robots 금지, 홈플러스 종이전단은 가격이 한글 수사("칠천팔백구십원")라 오독 위험, 롯데마트는 브라우저에서 그리는 구조, 킴스클럽은 공식 웹 전단 없음 → 보류.
- 오아시스마켓: robots.txt 없음, JSON-LD 없음(가격은 HTML 클래스에만).
- 다나와와 에누리는 운영사(커넥트웨이브)가 같다. 표본 3건에서 쿠팡·컬리·홈플러스는 판매처로 나오지 않았다.
- 확인 필요: 다나와 MCP의 서버 이용 가능 여부와 조건(커넥트웨이브 문의), 에누리·다나와의 식품 판매처 범위, 로우차트·오아시스 약관, 쿠팡이츠마트·배민B마트(추측: 앱 전용).
- 원칙(제안): 다나와를 1순위로 품목별 하루 한 번만 받아 캐시하고 robots 금지 경로는 받지 않는다. 약관이 금지하는 것은 영리목적 복제이고 이 앱은 비상업이지만, 법적 판단은 아니다.

## 2. 매장 가격 — 한국소비자원 참가격

- 168개 품목(604개 상품)을 격주로 조사(대형마트·슈퍼는 목요일), 전국 약 500개 판매점. 조사 대상: 이마트, 농협하나로마트, 롯데슈퍼, GS더프레시, 현대·신세계백화점, CU·GS25·세븐일레븐·이마트24. **홈플러스·롯데마트·킴스클럽은 없다.** https://www.price.go.kr/tprice/portal/pricenewsandtpriceintro/tpriceintro/getPriceIntro.do
- 공개 API: 공공데이터포털 "한국소비자원_생필품 가격 정보" https://www.data.go.kr/data/3043385/openapi.do (GW판 15158701). 무료, 자동 승인, 개발계정 하루 2,000회, 공공누리 1유형(출처 표시).
- 확인 필요: 실제 응답의 판매점별 가격·조사일 필드(키 발급 후), 두 API 중 존속할 쪽.

## 3. 농축수산물 시세 — KAMIS Open API

- 안내: https://www.kamis.or.kr/customer/reference/openapi_list.do
- 확인된 사실
  - 공공데이터포털을 통하면 승인 대기 없이 키를 받을 수 있다고 안내돼 있다.
  - 일별 부류별 도·소매가격(`action=dailyPriceByCategoryList`): 요청 변수 `p_cert_key`, `p_cert_id`, `p_returntype`, `p_product_cls_code`(01 소매/02 도매), `p_item_category_code`(100 식량작물, 200 채소, 300 특용작물, 400 과일, 500 축산물, 600 수산물), `p_country_code`, `p_regday`, `p_convert_kg_yn`. 응답 `dpr1`~`dpr7` = 조회일, 1일 전, 1주일 전, 2주일 전, 1개월 전, 1년 전, 평년 가격.
  - 기간 조회(`action=periodProductList`)는 1년치만.
  - 월별·연도별 API는 "축평원 데이터 제외".
  - 평년은 5년간(금년 제외) 최고·최저를 뺀 3년 평균.
- 확인 필요: 일별 API의 축산물 포함 여부(추측: 포함), 갱신 시각, 호출 한도.

## 4. 평점·후기

- 공식 API 가운데 별점·후기 수를 주는 곳은 없다(네이버 쇼핑 API에도 없었고, 쿠팡 파트너스 응답에도 없다).
- 페이지 구조화 데이터: 다나와 `aggregateRating`(평점·후기 수), 컬리 `reviewCount`(평점 없음). SSG·오늘의집은 화면에 평점이 보이지만 수집 거부·차단.
- 한국소비자원 비교공감: 소비자24 Open API는 2022-02-22부터 "서비스중지". 보고서는 게시판(최근 2026-10-06)과 공공데이터포털 파일(15099579, PDF·URL 목록)로만 있다. 식품보다 생활용품이 많다.
- 원칙(제안): 후기 본문은 작성자 저작권이므로 복제·요약하지 않는다. 평점·후기 수·출처 링크·기준일만 보여 준다.
- 확인 필요: 다나와 후기 수가 무엇을 합산한 숫자인지.

- **2026-10-19 정식 키로 확인한 사실**(실제 호출):
  - 주소는 `https://`로도 된다(인증서 정상). 앱은 https만 쓴다(키가 주소에 들어가므로).

I2620은 537줄이 441개 제품으로 저장됐다. **I2620은 부적합 검사 항목마다 한 줄**이고 같은 제품은 같은 `RTRVLDSUSE_SEQ`를 쓴다(537줄 중 96줄이 겹침, 겹친 줄끼리 다른 값은 `TEST_ITMNM`·`TESTANALS_RSLT`·`STDR_STND`뿐). 앱은 같은 번호의 사유를 " / "로 이어 한 행에 담는다(68개 제품이 항목 둘 이상). 그래서 I2620의 `sync_runs.rows`는 `total`보다 적은 것이 정상이다.

- 수집 방식(계획 ②): Edge Function `food-alerts-sync`가 세 서비스 전체를 받아 `grocery.food_alerts`에 upsert한다. 호출 비밀번호는 없고, 세 서비스를 모두 20시간 안에 받아 두었으면 받지 않으며(200 `skipped`), 30분 안의 재시도는 DB 잠금(`grocery.sync_lock`)으로 막는다(429 `cooldown`). 매일 07:00(한국 시간) GitHub Actions가 부른다.
- 확인 필요: 틀린 키일 때 응답이 서비스 이름 아래가 아닌 최상위 `RESULT`로 오는지(그러면 기록에 `NO-RESULT`로 남는다).
